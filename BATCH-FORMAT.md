# Weekly inbox contract (v1)

Update inbox.json on main with {"schema_version":1,"batches":[{"id":"week-YYYY-MM-DD","articles":[...exactly seven...]}]}.

Before every update fetch the latest file and use its current SHA. Append one unique batch per Friday, preserve earlier batches (maximum 52), and keep the complete file below 25 MB. Keep individual images compressed below 150 KB when practical. Do not create empty or fabricated articles to reach seven. An incomplete batch must be reported and held back.

Each article has: slug (unique lowercase hyphenated ASCII, never reuse), date (YYYY-MM-DD), display_date (Persian display date), title, excerpt, category, takeaway (strings), reading_minutes (integer), cover (figure), sections (array), sources (array of {title,url}). Each section has heading, paragraphs (string array), optional source_indices (zero-based source indices) and optional figure. Every source URL must be HTTPS. Each figure has src (data:image/jpeg;base64,... or PNG/WebP, valid actual image bytes, no generated imagery), alt, caption, width, height, credit:{author,url,license,license_url}; credit URLs must be HTTPS. Use only images with documented redistribution permission; identify third-party clinical cases as third-party, not Dr Amiri's cases. Do not put secrets or personal patient information here. This repository is public: pending articles can be read on GitHub even before website approval.

Set status=draft for every submitted article. The website independently forces imported articles to draft, and ignores any proposed approval/status. Batch imports are immutable by ID; corrections to an already imported batch must be made in the website admin. Website approval binds to the reviewed local revision and schedules seven consecutive dates in Asia/Tehran. Never write approval on the user's behalf.

Deployment: site package v7.4.7 or later must be installed manually before inbox synchronization works. Opening the authenticated admin imports new batches (at most once every five minutes per session); a manual refresh is also available. Approved entries appear on public requests at/after their scheduled timestamps. No AI API or GitHub Actions is required.
